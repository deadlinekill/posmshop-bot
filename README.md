## Что умеет бот

Клиент: регистрация с согласием на обработку персональных данных, каталог с
подразделами и страницами, поиск по названию или артикулу, корзина, оформление
заявки с комментарием, «Мои заявки» и повтор заказа.

Менеджер (роль `manager` в таблице `shop.users`): список активных заявок, карточка
заявки с расшифрованным телефоном клиента, смена статуса (клиент получает уведомление).
О новой заявке бот пишет в закрытый чат менеджеров, если задан `MANAGERS_CHAT_ID`.

## Установка

Нужны Python 3.10+ и PostgreSQL 15 или новее (проверено на PostgreSQL 16).

```bash
pip install -r requirements.txt
cp .env.example .env        # в Windows: copy .env.example .env
```

Заполните `.env`: токен бота от @BotFather, пароли четырёх ролей (случайные строки),
`PHONE_KEY` (не короче 16 символов) и `ADMIN_DSN` суперпользователя.
Случайный пароль удобно получить так: `python -c "import secrets; print(secrets.token_urlsafe(18))"`.

Чтобы работал мониторинг запросов, в `postgresql.conf` должно быть
`shared_preload_libraries = 'pg_stat_statements'` (после изменения перезапустите сервер).

Развернуть базу (создаст базу `posmshop`, роли, таблицы, права, RLS, аудит, каталог):

```bash
python scripts/setup_db.py
```

Скрипт можно запускать повторно: уже созданное он пропускает, а пароли ролей обновляет из `.env`.

## Запуск бота

```bash
python -m bot
```

Сделать пользователя менеджером (после того как он зарегистрировался в боте):

```sql
-- psql под postgres, база posmshop
UPDATE shop.users SET role = 'manager' WHERE tg_id = 123456789;
```

## Администрирование

* Резервная копия: `scripts/backup.sh` (cron, каждый день в 03:00). Пароль роли
  `backup_agent` положите в `~/.pgpass` с правами 600:
  `127.0.0.1:5432:posmshop:backup_agent:ПАРОЛЬ`.
* Проверка восстановления: `scripts/restore_check.sh` (cron, по понедельникам,
  от системного пользователя postgres).
* Перенос копий на внешнее хранилище раз в неделю (rsync) настраивается отдельно.
* Очистка журнала диалогов старше 90 дней (cron, еженедельно):
  `psql -d posmshop -c "SELECT shop.cleanup_dialog_log();"`
* Мониторинг: `psql -d posmshop -f sql/monitoring.sql`
* Конфигурация рабочего сервера: `config/postgresql.conf.sample` и `config/pg_hba.conf.sample`.

## Тесты

Тесты работают с  PostgreSQL: создают базу `posmshop_test`, применяют все
скрипты и удаляют её в конце. Нужна переменная `TEST_ADMIN_DSN` в `.env`.

```bash
python -m pytest -v
```

Что проверяется: все 9 сценариев таблицы 6 отчёта (отказ в доступе к журналу аудита,
запрет удаления заявок, изоляция клиентов через RLS, запрет менять сумму заявки,
отсутствие доступа отчётной роли к персональным данным, SQL-инъекции, правила
pg_hba.conf, запись в журнал аудита), шифрование телефонов, резервное копирование и
восстановление, а также сквозной сценарий бота от регистрации до смены статуса
менеджером (сообщения Telegram подменяются заглушкой, база настоящая).

Роли PostgreSQL общие для всего сервера, поэтому тесты задают им пароли из `.env`.
Если в `.env` пароли не указаны, тесты зададут случайные, и бот, работающий на том же
сервере, после этого нужно перезапустить с новыми паролями (`python scripts/setup_db.py`
вернёт пароли из `.env`).
